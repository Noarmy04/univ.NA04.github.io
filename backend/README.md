# UNIV NA04 익명 평가 및 대화

Supabase 프로젝트: univ-na04 (서울)

## 운영 동작

새 평가와 수정한 평가를 저장하면 익명으로 자동 공개합니다. 이전 개인 기록은 소급 게시하지 않습니다.
오늘의 강의 아래 공개 평가에서 익명 대화를 열 수 있습니다. 첫 참여 시 이용 안내 확인을 요청합니다.
대화는 10초마다 새 글을 확인합니다. 최근 평가 100개와 평가별 최근 메시지 100개를 표시합니다.

익명 세션은 브라우저에 보관되므로 데이터를 삭제하거나 다른 기기를 사용하면 이전 작성자로 접근할 수 없습니다.
개인 시간표와 과목 등록 정보는 브라우저별로 유지됩니다.

## 서버 제한

글쓰기 간격은 5초이며, 기본 금칙 표현을 반복 3회 사용하면 해당 익명 사용자의 글쓰기를 24시간 제한합니다.
금칙어 목록은 모든 유해 표현을 판별하지 못하므로 신고는 관리자가 검토해야 합니다.
신고는 na04_private.reports에서 확인합니다. members.blocked_until로 관리자 제한을 적용할 수 있습니다.
제한은 익명 사용자 기준이며 실제 사람의 재가입을 막는 학생 인증은 아닙니다.

## 데이터 접근

공개 RPC는 SECURITY INVOKER이며 비공개 스키마의 검증된 함수만 호출합니다.
테이블 직접 접근은 허용하지 않으며 공개 조회에 인증 ID, 이메일, 토큰을 포함하지 않습니다.
anonymous-config.js에는 브라우저 공개용 publishable key만 포함합니다.

적용한 스키마 변경 순서: anonymous.sql, private_rpc_boundary.sql.
Supabase의 Anonymous Sign-Ins 설정이 켜져 있어야 합니다.

## 검증

두 실제 익명 사용자의 가입, 평가 공개와 상호 조회, 익명 답글, 안내 전 게시 차단을 API로 확인했습니다.
트랜잭션 기반 검사로 글쓰기 간격, 3회 위반 제한, 사용자 간 덮어쓰기 방지와 식별정보 비노출을 확인했습니다.
브라우저에서 공유 버튼 없이 저장한 평가가 공개 목록에 표시되는 것과 경고 화면을 확인했습니다.
보안 검사 경고는 없었으며, 검증용 기록과 익명 사용자는 정리했습니다.

## 다음 변경 사항 적용 대기

익명 대화를 별도 메뉴로 분리하고 해당 과목 평가를 완료한 사용자만 대화를 읽고 작성하도록 변경했습니다.
서버 변경 파일은 require_course_review_for_discussion.sql이며, 현재 운영 데이터베이스에는 적용하지 않았습니다.
배포 시에는 이 서버 변경을 먼저 적용·검증한 후 프런트엔드를 수동 배포해야 합니다.
기존 첫 참여 안내와 신고·금칙 표현 제한은 유지합니다.
로컬 검증용 서버에서 미평가 차단 → 과목 평가 → 대화 참여 → 안내 확인 → 작성창 표시를 확인했습니다.
실제 서버의 새 참여 제한 함수 실행 검증은 데이터베이스 적용 승인 후 진행해야 합니다.
