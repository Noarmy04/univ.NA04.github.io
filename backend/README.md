# UNIV NA04 익명 평가 및 대화

Supabase 프로젝트: univ-na04 (서울)

## 에타 링크 가져오기

Edge Function `everytime-import`는 JWT 검증을 켠 상태로 운영합니다. 에타 공개 조회 주소만 사용하고, 쿠키·공유자 정보·로그인 비밀번호를 전달받거나 저장하지 않습니다.
함수의 index.ts와 deno.json은 backend/everytime-import에 있습니다. 배포 도구에는 이 두 파일과 루트의 everytime-model.js를 함수의 같은 디렉터리 파일로 전달합니다. 프런트엔드와 함수는 동일한 모델 소스를 사용합니다.
요청·응답 크기와 외부 요청 시간을 제한합니다. 실행 인스턴스 내에서 사용자 토큰별 분당 10회 제한을 적용하지만, 여러 인스턴스에 걸친 강한 전역 제한은 아닙니다.
2026-11-10 실제 공개 링크로 8개 강좌·11개 시간대를 조회하고 모든 강좌의 ERICA 수업번호·교수를 대조했습니다. 미리보기에서 새 버전 저장·새로고침 유지·평가 목록 연결을 검증했습니다.

## 운영 동작

토론 그룹 변경은 group_discussions_by_offering.sql → canonical_discussion_times.sql 순서로 적용했습니다. discussion_helpers.sql은 현재 정규화·분반 비교 함수의 소스입니다.
평가의 course.offering에 학기·수업번호·주간 시간이 들어갑니다. 시간이 있으면 같은 주간 시간표를 기준으로 묶고, 시간이 없을 때만 수업번호를 사용합니다. 날짜나 평가 세션은 토론방 구분에 사용하지 않습니다.
sync_offerings는 인증된 본인의 client_id에 해당하는 평가만 기존 시간표와 연결합니다. 처음 게시하는 평가는 시간표 정보를 함께 저장하며, 이전 비공개 평가는 이 작업으로 자동 게시하지 않습니다.
메시지는 기존 review_id와 내용 그대로 보존하고, 조회 때 같은 토론 그룹에 연결된 평가의 메시지를 모읍니다. 익명 별명도 그룹 안에서 일관되게 표시합니다. 토론 열람·전송의 참여 제한은 같은 그룹의 본인 평가 존재 여부를 확인합니다.
test_grouped_discussions.sql로 날짜 간 메시지 합침, 다른 시간대 차단, 미평가 차단, 소유권 검사, 기존 기록 연결과 익명성을 확인했습니다. 검증 자료는 모두 롤백합니다.

공유 평가 목록은 서버에 본인의 평가를 1개 이상 등록한 익명 사용자만 조회할 수 있습니다. 미인증 또는 미평가 요청에는 평가 내용 없이 locked=true와 빈 records만 반환합니다.
require_review_for_feed.sql을 적용했으며, test_review_feed_gate.sql로 미인증·미평가 차단, 안내 동의만으로 우회 불가, 평가 후 조회, 식별정보 비노출과 기존 과목별 토론 제한을 롤백 검사했습니다.

새 평가와 수정한 평가를 저장하면 익명으로 자동 공개합니다. 이전 개인 기록은 소급 게시하지 않습니다.
오늘의 강의 아래 공개 평가에서 익명 대화를 열 수 있습니다. 첫 참여 시 이용 안내 확인을 요청합니다.
대화는 10초마다 새 글을 확인합니다. 최근 평가 100개와 평가별 최근 메시지 100개를 표시합니다.

익명 세션은 브라우저에 보관되므로 데이터를 삭제하거나 다른 기기를 사용하면 이전 작성자로 접근할 수 없습니다.
개인 시간표와 과목 등록 정보는 브라우저별로 유지됩니다.

## 서버 제한

글쓰기 간격은 5초이며, 기본 금칙 표현을 반복 3회 사용하면 해당 익명 사용자의 글쓰기를 24시간 제한합니다.
금칙어 목록은 모든 유해 표현을 판별하지 못하므로 신고는 관리자가 검토해야 합니다.
신고는 na04_private.reports에서 확인합니다. members.blocked_until로 관리자 제한을 적용할 수 있습니다.
제한은 익명 사용자 기준이며 실제 사람의 재가입을 막는 학생 인증은 아닙니다.

## 데이터 접근

공개 RPC는 SECURITY INVOKER이며 비공개 스키마의 검증된 함수만 호출합니다.
테이블 직접 접근은 허용하지 않으며 공개 조회에 인증 ID, 이메일, 토큰을 포함하지 않습니다.
anonymous-config.js에는 브라우저 공개용 publishable key만 포함합니다.

적용한 스키마 변경 순서: anonymous.sql, private_rpc_boundary.sql, require_course_review_for_discussion.sql.
Supabase의 Anonymous Sign-Ins 설정이 켜져 있어야 합니다.

## 검증

두 실제 익명 사용자의 가입, 평가 공개와 상호 조회, 익명 답글, 안내 전 게시 차단을 API로 확인했습니다.
트랜잭션 기반 검사로 글쓰기 간격, 3회 위반 제한, 사용자 간 덮어쓰기 방지와 식별정보 비노출을 확인했습니다.
브라우저에서 공유 버튼 없이 저장한 평가가 공개 목록에 표시되는 것과 경고 화면을 확인했습니다.
보안 검사 경고는 없었으며, 검증용 기록과 익명 사용자는 정리했습니다.

## 익명 대화 참여 조건

익명 대화를 별도 메뉴로 분리하고 해당 과목 평가를 완료한 사용자만 대화를 읽고 작성하도록 변경했습니다.
서버 변경 파일 require_course_review_for_discussion.sql을 운영 데이터베이스에 적용했습니다.
학교, 과목명, 교수명이 일치하는 본인 평가가 있어야 대화를 읽거나 작성할 수 있습니다. 날짜와 세션은 달라도 됩니다.
기존 첫 참여 안내와 신고·금칙 표현 제한은 유지합니다.
로컬 검증용 서버에서 미평가 차단 → 과목 평가 → 대화 참여 → 안내 확인 → 작성창 표시를 확인했습니다.
운영 데이터베이스에서도 임시 사용자와 롤백 검증으로 미평가·다른 과목 차단, 해당 과목 평가 후 참여와 안내 동의를 확인했습니다.
